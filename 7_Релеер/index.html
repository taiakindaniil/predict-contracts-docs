Релеер

Архтектура

Релеер состоит из 3 модулей + 1 общий:

  • ton-module – модуль, взаимодействующий с сетью TON (слушает контракт фабрики, взаимодейтсвует с predict-contracts)
  • polygon-module – модуль, взаимодействующий с сетью Polygon (отправляет запросы в Adapter / OOv2, слушает транзакции)
  • api – модуль REST API, через который происходит взаимодействие с релеером (инициализация маркетов, разрешение вопросов в ручном режиме)
  • shared – общий модуль для взаимодействия с Redis Streams, логгером сообщений pino

Настройка

Перед тем, как настраивать релеер, убедитесь, что вы задеплоили контракт Adapter в сети Polygon и контракт Factory в сети TON.

Взамодействие c API

1. Создание события

POST /api/v1/events/create

Описание Добавляет событие в очередь на деплой в TON. После успешного деплоя запускается процесс инициализации вопроса в UMA (Polygon).

Тело запроса (JSON)

{
  "clientId": "optional-client-id",
  "name": "Название события",
  "description": "Описание события (опционально)",
  "imageUrl": "https://example.com/image.png",
  "symbol": "EVT",
  "socialLinks": ["https://x.com/project", "https://t.me/channel"],
  "extraMetadata": {
    "category": "sports",
    "tags": ["football", "world-cup"]
  },
  "ancillaryData": "q: title: Will Metamask launch a token in 2025?, description: This market will resolve to 'Yes' if Metamask officially launches a token by December 31, 2025, 11:59 PM ET. Otherwise, this market will resolve to 'No'. The token must be actively and publicly transferable and tradable. Announcements alone do not qualify The primary resolution source for this market will be information from Metamask, however a consensus of credible reporting will also be used. market_id: 704067 res_data: p1: 0, p2: 1, p3: 0.5. Where p1 corresponds to No, p2 to Yes, p3 to unknown/50-50.",
  "rewardToken": "0x41e94eb019c0762f9bfcf9fb1e58725bfb0e7582",
  "reward": "0.1",
  "proposalBond": "0.01",
  "liveness": 60
}

Поля

  • clientId (string, optional) — ID клиента/источника события.
  • name (string, required) — название события.
  • description (string, optional) — описание события.
  • imageUrl (string, optional) — URL изображения события.
  • symbol (string, required) — символ/тикер токена события.
  • socialLinks (array of strings, optional) — список ссылок на соцсети.
  • extraMetadata (object, optional) — произвольные дополнительные метаданные.
  • ancillaryData (string, required) – полный запрос в UMA.
  • rewardToken (string, required) – адрес токена награды и залога.
  • reward (number, required) – награда, которую получит proposer.
  • proposalBond (number, required) – ставка, которую делают участники протокола UMA, чтобы предложить ответ.
  • liveness (number, optional) – время в секундах, в течение которого могут оспорить предложенное решение.

Ответы

  • 202 Accepted
{
  "queued": true,
  "id": "1685737472763-0",
  "type": "create_event"
}
  • 400 Bad Request – невалидные данные
  • 500 Internal Server Error – ошибка добавления в очередь

Представлен пример взаимодейсвтия с релеером через REST API модель посредством запросов через curl.

curl -X POST http://localhost:3000/api/v1/events/create \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Test name",
    "symbol": "PEDICTTEST",
    "clientId": "backend-1"
}'
